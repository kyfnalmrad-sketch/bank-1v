# خطة إضافة بنك التضامن على الفرع `1v11n` — النسخة المحدثة

## 1. الملخص التنفيذي

يُنفّذ بنك التضامن كمسار مستقل داخل الفرع `1v11n`. يحافظ المسار على عزل بيانات بنك الكريمي والبنك التجاري اليمني، ويستخدم قالب بنك التضامن وبياناته ورموزه الخاصة. اكتملت مراحل تأسيس المسار وربط الإدخال والاستيراد وتنفيذ المعاينة والتصدير. تبقى مرحلة الاعتماد والتثبيت النهائية، وتشمل المراجعة البصرية بالبيانات الفعلية ومصفوفة العزل الشاملة ثم اعتماد النسخة النهائية.

> **قاعدة العزل:** لا يجوز لمسار التضامن قراءة أو كتابة بيانات الكريمي أو YCB. ويجب أن تكون الهوية، ومساحة الإدخال، وسجل الحركات، والمعاينة، والطباعة، والتصدير، وSnapshot، وHistory، وQR، وPDF417 مستقلة لكل بنك.

## 2. نطاق الخطة

يشمل العمل مسار بنك التضامن فقط على الفرع `1v11n`. ولا يشمل دمج الفرع مع `1v11` أو تعديل قوالب الكريمي وYCB أو تغيير منطق تشغيلهما، باستثناء الطبقات العامة الضرورية لبقاء خيارات البنوك وعزلها.

يعتمد كشف الحساب على قالب HTML الرسمي المرسل باسم `local-tadhamon-ycb-refined-updated.html`. ويعتمد بيان الحالة على قالب `YBK11-4.pdf`. تُعامل البيانات الموجودة في القالبين كبيانات مرجعية بصرية فقط، ولا تدخل في التشغيل كقيم افتراضية.

## 6. المرحلة الثالثة: القالب والمعاينة والتصدير

### الهدف

ربط كشف الحساب وبيان الحالة بالقالبين الرسميين، وإزالة المعاينة السابقة التي كانت تسقط إلى تصميم أو هوية بنك الكريمي.

### 6.1 كشف الحساب

تم إنشاء مولد مستقل باسم `renderTadhamonStatementPages`. يعتمد المولد بنية قالب HTML المرسل، وليس الخلفية وحدها. وتشمل البنية الرأس، والحقول، وملخص الأرصدة، وجدول الحركات، وصف الإجماليات، والملاحظات، والتذييل.

تُستبدل القيم الوهمية في كل صفحة بالقيم الحالية من حالة التضامن. وتُقسم الحركات إلى صفحات بحد أقصى 18 حركة في الصفحة، مع تحديث رقم الصفحة وعدد الصفحات والرصيد والإجماليات والرموز لكل صفحة.

### 6.2 الحقول المتغيرة في كشف الحساب

| منطقة القالب | القيمة الديناميكية |
|---|---|
| Customer Name | اسم العميل من جلسة التضامن |
| Address | عنوان العميل |
| Passport Number | رقم الجواز |
| Print Date وPrint Time | تاريخ ووقت إنشاء المعاينة |
| Branch Name | فرع العميل |
| Account Number | رقم الحساب |
| The Period | بداية ونهاية الفترة |
| Currency | عملة الحساب |
| Page | رقم الصفحة وعدد الصفحات |
| Opening Balance | الرصيد الافتتاحي المحسوب |
| Total Credit | إجمالي الإيداعات المقبولة |
| Total Debit | إجمالي السحوبات المقبولة |
| Closing Balance | رصيد آخر حركة أو الرصيد المحسوب |
| جدول الحركات | الحركات المعتمدة من Excel |
| Statement Reference | مرجع الكشف الخاص بالتضامن |

### 6.3 بيان الحالة

تم ربط بيان الحالة بخلفية قالب `YBK11-4.pdf` المستخرج إلى أصل صورة مستقل. تظهر فوق القالب بيانات بيان الحالة الحالية، مثل اسم البنك وبيانات العميل والأرصدة والإجماليات ومرجع الكشف وQR.

لا يستخدم بيان التضامن خلفية أو اسم أو QR خاصًا بالكريمي. كما لا يتغير مسار بيان الحالة الخاص بالكريمي أو YCB.

### 6.4 QR وPDF417

تم فصل حمولات التحقق الخاصة بالتضامن عن حمولات الكريمي وYCB. تحتوي الحمولة على هوية `TADHAMON BANK` ومرجع الكشف ورقم الصفحة وعدد الصفحات وملخص الحركة، حسب نوع المستند.

تم أيضًا إصلاح ظهور PDF417 داخل رأس كشف الحساب. أصبح له حجم ووضوح ثابتان، ويُعرض من خلال الصورة التي يولدها `bwip-js` في موضع الباركود المحدد في القالب.

### 6.5 المعاينة والطباعة وحفظ PDF

أصبح اختيار المستند يعتمد على البنك الحالي:

| البنك | كشف الحساب |
|---|---|
| الكريمي | مولد الكريمي الحالي |
| YCB | قالب YCB المعتمد |
| التضامن | مولد قالب التضامن الكامل |

تستخدم أزرار المعاينة والطباعة وحفظ PDF نفس HTML الخاص بالمسار الحالي. ولا يمكن لمسار التضامن عرض كشف الكريمي أو طباعته من خلال التفرع الحالي.

هذه المرحلة لم تُغلق نهائيًا بعد، وتبقى الأعمال التالية مطلوبة قبل اعتبار المسار معتمدًا إنتاجيًا.

| المهمة | الإجراء المطلوب | معيار القبول |
|---|---|---|
| اختبار المسارات الثلاثة | تجربة الكريمي وYCB والتضامن في جلسات منفصلة | نجاح التشغيل دون تغير في قوالب المسارات القائمة |
| اختبار العزل المتبادل | تبديل البنك ثم الحفظ والاستعادة والمعاينة والتصدير | عدم ظهور أي بيانات أو هوية من بنك آخر |
| اختبار صفحات متعددة | استيراد أكثر من 18 حركة | ظهور كل الصفحات مع أرقام صحيحة وإجماليات صحيحة |
| اختبار القالب بصريًا | مقارنة كشف فعلي بالقالب المرسل | اختلاف البيانات فقط دون اختلاف غير مقصود في التصميم |
| اختبار PDF417 | فحص ظهوره وقابليته للقراءة في كل صفحة | وجود باركود مستقل في كل صفحة |
| اختبار QR | قراءة QR والتحقق من الحمولة | ظهور `TADHAMON BANK` وعدم ظهور هوية الكريمي أو YCB |
| مراجعة البيانات الوهمية | البحث عن قيم العميل والحركات التجريبية | عدم وجودها في المخرج التشغيلي |
| مراجعة النصوص الرسمية | اعتماد النصوص النهائية للملاحظات والتذييل | موافقة الجهة المالكة للقالب |
| التوثيق | تحديث تقرير المرحلة النهائية | توثيق الملفات والاختبارات والقيود |
| الاعتماد | إنشاء commit نهائي للمرحلة الرابعة | موافقة المراجعة النهائية على الفرع |

## 10. سياسة التغيير

يُنفذ العمل على الفرع `1v11n` فقط. لا يُدمج الفرع مع `1v11` ضمن هذه المرحلة. ولا تُعدل قوالب الكريمي أو YCB إلا عند الحاجة في طبقة عامة واضحة ومختبرة. لا تُستخدم القيم الوهمية من القوالب كبيانات تشغيلية. يجب أن يُثبت كل تغيير مهم في commit مستقل مع نتيجة اختبار واضحة.

## 11. الحالة الحالية والقرار التالي

الحالة الحالية هي **المرحلة الثالثة مكتملة وظيفيًا**، مع اعتماد قالب كشف الحساب الكامل وإصلاح ظهور PDF417. الخطوة التالية هي تنفيذ اختبارات المرحلة الرابعة باستخدام ملف Excel واقعي وبيانات عميل واقعية، ثم إجراء مراجعة بصرية نهائية واعتماد الفرع.
