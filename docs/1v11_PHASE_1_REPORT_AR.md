# تقرير المرحلة الأولى — فرع `1v11`

## الخلاصة

تم تجهيز نسخة عمل محلية من آخر نسخة معتمدة على `origin/1v11`. لم يتم رفع أي تغيير إلى GitHub، ولم يتم دمج أي فرع. بقيت مسارات بنك الكريمي والبنك التجاري اليمني منفصلة، مع إبقاء قوالب المستندات الرسمية ومسارات الاستيراد والمعاينة والطباعة الحالية دون تعديل وظيفي.

أضيفت في مسار البنك التجاري اليمني طبقة تنظيم تجريبية للواجهة فقط. تعرض الطبقة خمس وحدات واضحة: المعلومات، السجلات والاستيراد، المعاينتان، التصدير والطباعة، والسجلات السابقة. الأزرار تستخدم وظائف النظام الحالية نفسها، ولا تنشئ مسارًا جديدًا أو تنقل البيانات بين البنكين.

كما طُبق طلب الكريمي الخاص بتوقيعات بيان الحالة. بقيت مواضع التوقيعات كما هي، وأصبح حجمها `12pt`، وأصبحت القيمة بخط عريض، وأسماء الموظفين بخط عادي أسود.

## ما تم تنفيذه

| البند | التنفيذ | النطاق |
|---|---|---|
| فرع العمل | إنشاء فرع محلي `1v11` متتبعًا لآخر `origin/1v11` | إدارة Git فقط |
| لوحة YCB التجريبية | إضافة خمس بطاقات تنظيمية في واجهة الإدخال | البنك التجاري اليمني فقط |
| ربط البطاقات | ربط السجلات، المعاينة، التصدير، والطباعة بوظائف النظام الحالية | دون تغيير المسارات |
| توقيعات الكريمي | حجم 12pt، القيمة عريضة، أسماء سوداء عادية | بيان الحالة فقط |
| القوالب الرسمية | لم تُعدّل قوالب كشف YCB أو ملفات PDF الأصلية | حماية الأصل |

## نتيجة التحقق

نجح فحص TypeScript باستخدام `pnpm run check`.

نجحت اختبارات الواجهة والمنطق والقوالب، وعددها 37 اختبارًا. فشل اختبار قاعدة بيانات PostgreSQL فقط لأن المتغير السري `RENDER_POSTGRES_URL` غير متاح في البيئة المحلية. هذا فشل بيئي وليس فشلًا في تعديلات الواجهة.

لم يتم تشغيل اختبار اتصال قاعدة البيانات على عنوان بديل، ولم يتم تغيير أي إعدادات أسرار.

## خطة العمل ذات السبع مراحل

### المرحلة الأولى: التدقيق وتثبيت خط الأساس

تتضمن مراجعة فروع `1v` و`1v11`، تحديد الملفات الرسمية، توثيق مسارات كل بنك، وحماية ملفات القوالب وملفات QR والباركود من التغيير غير المقصود. مخرج المرحلة هو تقرير خط أساس وموافقة على نقطة الانطلاق.

### المرحلة الثانية: خريطة النماذج الرسمية

تتضمن تحليل ورقة كشف الحساب وورقة البيان لكل بنك، واستخراج النصوص، أحجام الخطوط، الألوان، أبعاد الجداول، مواضع QR والباركود، الترويسات، التذييلات، التوقيعات، وقواعد الصفحات. بعد استلام أوراق بنك التضامن، تُضاف خريطة مستقلة له دون نسخ هوية بنك آخر.

### المرحلة الثالثة: نموذج البيانات والرموز

تتضمن تحديد حقول الإدخال الرسمية لكل بنك، أرقام المراجع، أرقام الحسابات، قواعد الرصيد، صيغ QR، صيغ الباركود، رقم الصفحة، عدد العمليات، والحقول التي تنتقل إلى البيان أو الكشف. تكون لكل بنك هوية رموز مستقلة ومسار تخزين مستقل.

### المرحلة الرابعة: تنظيم واجهات الإدخال

تتضمن ترتيب واجهة كل بنك إلى: المعلومات الشخصية، المعلومات المرجعية والأرقام، المعلومات المالية، وسجل العمليات. تُنظم الحقول والمعاينات دون تغيير أسماء المسارات أو منطقها. النموذج الحالي المنفذ في YCB هو نموذج مراجعة لهذه المرحلة، ولا يعتمد نهائيًا قبل الموافقة.

### المرحلة الخامسة: السجلات والمعاينات والتصدير

تتضمن توحيد صندوق السجلات، استيراد Excel، التعديل، القبول، التحديث، والمعاينتين الرسميتين. يجب أن يتغير طول كشف الحساب بحسب عدد العمليات، وأن تعرض المعاينة جميع الصفحات المطلوبة بدل صفحة ثابتة. تُجمع أزرار المعاينة الفردية والكلية والطباعة والحفظ PDF في صندوق تصدير واضح.

### المرحلة السادسة: بنك التضامن

تبدأ بعد استلام الورقة الرسمية للبيان وكشف الحساب. يُنشأ مسار مستقل مشتق من النسخة المعتمدة، ويُضاف بنك التضامن كمساحة منفصلة مع حقوله وأرقامه الرسمية وقوالبه وQR والباركود الخاص به. لا يُعاد استخدام هوية YCB أو الكريمي داخل مستندات التضامن إلا في وظائف النظام العامة التي لا تتعلق بهوية البنك.

### المرحلة السابعة: الاختبار والمراجعة والاعتماد

تتضمن اختبارات المسارات الثلاثة، اختبار تبديل البنك، اختبار استيراد السجلات، اختبار الصفحات المتعددة، اختبار التعديل والترحيل والتحديث، اختبار الطباعة الفردية والكلية، وفحص بصري PDF مقابل الأصل الرسمي. عند كل تصميم أو تغيير بصري، يُقدم ملف معاينة PDF قبل الاعتماد. لا يتم رفع أو تحديث GitHub إلا بعد موافقة صريحة على مخرج المرحلة.

## سياسة الرفع والموافقة

سأعمل محليًا وأحفظ كل مرحلة في commit واضح. عند اكتمال كل مرحلة سأرسل تقريرًا مختصرًا، وأرفق المعاينة المطلوبة، ثم أتوقف لطلب موافقة الرفع والتحديث. لن أنفذ `git push` أو دمجًا أو تحديثًا خارجيًا دون الموافقة على مخرج المرحلة المحددة.

## الخطوة التالية

الخطوة التالية هي مراجعة معاينة لوحة YCB التجريبية. بعد الموافقة على شكلها، تُستكمل إعادة تنظيم صندوق الإدخال والسجلات والمعاينات والتصدير مع الحفاظ على كل مسار قائم. وبعد ذلك يمكن استقبال الورقة الرسمية لبنك التضامن لتحليلها في المرحلة الثانية الخاصة بالنماذج.
